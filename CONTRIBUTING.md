# Как прислать изменения

Черновик; полная версия — этап 7 плана.

1. Сделайте fork, создайте ветку и откройте PR в `develop`.
2. На каждый push в PR автоматически запускаются юнит-тесты (GitHub Actions).
3. Когда юнит-тесты зелёные, мейнтейнер смотрит код и ставит метку `ok-to-test` —
   это запускает полную внутреннюю проверку **для текущего коммита**.
4. Любой новый push в PR снимает метку: одобрение привязано к конкретному SHA,
   и мейнтейнер должен одобрить новую ревизию заново.
5. После одобрения не делайте rebase и force-push без необходимости — это тоже новый
   SHA и повторное одобрение.
6. PR, добавляющие или меняющие `.gitlab-ci.yml`, не принимаются: конфигурация
   внутреннего CI хранится отдельно.
